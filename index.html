Reports

The download is an Excel workbook: a Summary tab with every breakdown below, then one tab per project manager and one per job with the day-by-day detail. Under narrows everything to one foreman's, superintendent's or PM's people, by the reporting chain set on the Employees tab.

Download to ExcelAdman's own daily and weekly forms, one file per batch

Weekly: one tab per PM on the weekly form, a block per job per week (night blocks are marked). Job descriptions land on the Monday to Sunday lines under WORK DESCRIPTION. A Totals tab comes along.

Daily: one tab per day worked, on the Daily Time & Material form, one form per job.

BillingRates live on the Employees tab; PM and job overhead and profit on the Jobs tab

Overhead and profit ("10 and 5") are added on top of labor and material to get what a job is billed, and print on their own lines of the Daily Time & Material form. Each PM can set his own pair on the Jobs tab, and any job can override either figure. Changes only affect how sheets are totalled from now on: nothing already exported changes.

Tablet screen

Every device opens on the keypad. A crew number clocks in; a super, PM or admin number opens the office at that level. The office passcode is a spare key for setup, before anyone has a number.

Sync (Supabase)

Leave these blank and everything stays on this device. Fill them in and every tablet and office machine set up the same way shares one set of books, and nothing is lost if a tablet dies.

These tables live in their own schema (use field), so this can share a Supabase project with the prefab shop app without the two ever touching each other's data. Run schema.sql once in the SQL editor, then add the schema under Settings → API → Exposed schemas. Row-level security is on: the anon key alone can read nothing.

Device sign-in

Every device signs in once. A tablet login can punch and request time off and never receives rates. A super login sees sheets but no dollars. PM and admin logins receive rates. The database enforces this, not the page. Accounts are created in Supabase → Authentication, then given a role in field.users.
